
There is a display form, and an recorded form:

1. recorded form:

extent-literal:: <escape><header>[<payload>] EoEI

1.1 escape

This is a value chosen to be illegal in all the target languages that the recorded form will be embedded.  In gen 2 we used an opening unicode quote which was 3 bytes long, and we had a closing unicode quote to the right of the payload. I suggest that an ASCII control character would be better as it is smaller.  The proper character for this, the one original designed for this very purpose, is the ASCII 'escape' character.

1.2 payload

This is a byte array. The leftmost byte of the payload array is the right-neighbor to the rightmost byte of the header.  The index of the rightmost byte of the payload array is called the 'extent'.   When extent is zero, the payload is one byte long.

However, the payload is not present in a null literal.

1.3 header

The leftmost byte of the header is the right-neighbor byte of the escape value.

However, though it has a leftmost byte, the header is treated as a bit array.  The leftmost bit of the leftmost byte is at bit index 0.  Zero padding is used to complete the rightmost byte of the header bit array.

```
10  intermediate tile marker

0   rank one rightmost tile marker

110   rank two rightmost tile marker

1110   rank three rightmost tile marker

etc.

```

Tile is 5 bits.

left to right scan

extent-integer::<format is rank1>
                       0├── null
                       1├── uninterpreted
                       2├── pair-list_only
                       3├── code-point
                       4├── ASCII
                       5└── UTF8
                    ...
                      32

syntax continuation depends on value of format, and/or its termination

  format == null::  EoEI

  format == uninterpreted:: <extent is rank1> <payload> EoEI

  format == list^2_only::  <list^2 is rank 3> EoEI

  format == codepoint:: <extent>[style [list^2]] EoEI
     if <extent> terminates rank3 then EoEI
     else <extent> must terminate rank2 and <style> follows
        if <style> terminates rank3 then EoEI
          else <style> must terminate rank2 and <list^2> follows.


list^2`:: <list>* EoEI;  <pair>* is rank 2

list:  <cint>* rank 2

cint:: rank1

Alternative regular approach, two bit tile tree building control.  5 bit tile.

tree depth first
0 atom
100 open with given tile
101 close with given tile
110 close n, count - 2 given in tile
111 close all with given tile

tree breadth first
0: atom
10: branch, "here is the head tile for a new list on the next level"
110: finish current list with this tile, proceed to next list on this level, if no next list go to first branch next level, if no next level then finished

    0: atom (leaf child of current active parent)
    10: branch (child of active parent is a list, this is the head, enqueue it to become a parent later)
    110: finish current list with this tile (dequeue next parent from FIFO and make it active. If queue empty, exit).


tree breadth first
start with an active singleton list
0: append this tile as a right-neighbor
10: here is the leftmost tile for a new list on the next level, enqueue it.
110: here is a rightmost tile, (dequeue next parent from FIFO and make it active. If queue empty, exit).

(a (b c) d) : [0 a] [10 b] [110 d] [110 c]
