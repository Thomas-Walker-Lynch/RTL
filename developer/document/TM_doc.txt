# TTCA and TM Ontology & Terminology Reference

Author of TCA: Thomas Walker Lynch
Author of this summary: Gemini
Context: This document defines the precise theoretical and operational terminology for the Topology of Computational Arrays (TTCA) and the Tape Machine (TM) interface architecture. 

## 1. Topological vs. Temporal Axioms
The core of TTCA relies on strictly separating the static, spatial structure of memory from the temporal act of traversing it. 

* Topological (Spatial) Terms: `left`, `right`, `leftmost`, `rightmost`. These describe the immutable physical or logical arrangement of cells.
* Temporal (Execution) Terms: `first`, `last`, `next`, `previous`. These describe the sequence of access during a scan. 
* The Independence Rule: Topological position is independent of scanning order. The `first` cell scanned could be the `rightmost` cell, the `leftmost` cell, or any arbitrary cell. 
* The "In-Between" Fallacy: There is no spatial "in-between" for cells. Cells possess discrete neighbor relationships. A boundary points *at* a cell, not between cells. Interstitial mapping requires a specific isomorphic ruleset (e.g., "insert to the left of cell X") rather than addressing an empty void between X and Y.

## 2. TTCA Core Terminology
* Tape / Array: An ordered sequence of discrete cells.
* Cell: The atomic unit holding data.
* Leftmost Cell: The structurally initial cell on the tape. Topologically, its index is 0.
* Rightmost Cell: The structurally terminal cell *included* on the tape. This is an inclusive bound.
* Rightmost Right-Neighbor: The theoretical cell located one discrete position to the right of the `rightmost` cell. A tape area is not guaranteed to have one, but it serves as the exclusive boundary marker for traversal logic (e.g., Emacs `point-max` logic).
* Extent: The index of the `rightmost` cell. It defines the required bit size of an index register. When speaking of arrays of bytes, extent is the maximum byte index.
* Length: A count of cells in an array. Length is exactly 1 plus the extent. Unlike extent, length can overflow an index register.
* Position: An index indicating a specific cell. (Note: Emacs buffer positions are 1-based and differ mathematically from 0-based TTCA topological indexes).

## 3. Tape Machine (TM) Interface Ontology
A Tape Machine is not a data structure; it is an interface consisting of combinational logic and state variables applied to a substrate (a list, string, or buffer).

* Substrate / Target: The underlying data structure being operated upon.
* Cueing (`cue-leftmost`, `cue`): Moving the TM's internal state (the tape head) to a specific topological position.
* Reading (`read`, `read-type`): Inspecting the cell at the current cued position. This operation is idempotent; it yields the same result repeatedly until the TM steps.
* Stepping (`step`): Advancing the TM's internal state to the `right-neighbor`.
* Boundary Evaluation (`has-right-neighbor`, `on-rightmost`): Validating the presence of topological neighbors to safely govern First/Rest iterative loops.
* Entanglement (`entangled-copy`): Creating a new TM instance that shares the exact same underlying substrate but maintains an independent cue position.

## 4. Relational Ontology (Machine to Machine)
Historical metaphors like "parent/child," "nested," or "step-in" are discarded because they improperly imply a structural call-stack hierarchy or physical containment.

* Interface-Driven Data Flow: A tape machine does not "contain" another machine. Instead, *a working function writes a given machine to a returned machine.*
* Payload Extraction (BreadBoxes): When processing raw binary within text streams, the binary sequence is topologically extracted from the host buffer. The host buffer is left with a zero-length interstitial structural overlay. The binary data is bound to a new, distinct TM instance generated by a `make-if` function. 

## 5. Control Flow: The First/Rest Loop
TTCA traversal avoids mid-loop escapes and evaluates bounds tightly to prevent out-of-bounds memory access.

1. First (The Cue): The machine evaluates the initial cell's valid state and simultaneously checks the `has-right-neighbor` boundary condition inside the initial variable bindings.
2. Rest (The Step): The loop condition tests the bound. Inside the loop body, the machine `step`s, performs work, and explicitly re-evaluates both the work output and the boundary condition at the absolute bottom of the loop. This maps functionally to Tail Call Optimization (TCO) but executes iteratively.
